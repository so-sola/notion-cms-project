# ROADMAP: Notion 포트폴리오 쇼케이스

> 이 문서는 `docs/PRD.md`를 기준으로 실제 개발 순서를 정의합니다.
> 원칙: **골격 → 공통 모듈 → 핵심 기능 → 추가 기능 → 최적화/배포** 순으로 진행하며,
> 각 단계는 이전 단계의 산출물 위에서만 안전하게 시작합니다.

> ⚠️ 참고: 이 프로젝트는 Next.js 16 기반이며 학습 데이터 상의 관례와 다른 breaking change가 있을 수 있습니다.
> 코드 작성 전 `node_modules/next/dist/docs/`의 관련 가이드를 확인하세요 (`AGENTS.md` 지침).

## 1단계: 프로젝트 초기 설정 (골격 구축)

### 할 일
- Next.js 16 + TypeScript 프로젝트 초기화
- Tailwind CSS 설정
- shadcn/ui 초기화 (`components.json`, 기본 테마)
- 폴더 구조 설계 (`app/`, `lib/`, `components/`, `types/` 등)
- ESLint/Prettier 등 기본 코드 품질 도구 설정
- Notion Integration 생성 및 Notion 데이터베이스 스키마 구성
  (제목, 설명, 썸네일, 태그, 링크, 공개여부, 정렬순서)
- 환경 변수 틀 마련 (`NOTION_API_KEY`, `NOTION_DATABASE_ID`) — `.env.local` / `.env.example`

### 왜 이 순서인가
모든 후속 단계(컴포넌트, API 연동, 기능 구현)는 프로젝트 골격과 Notion DB 스키마가 먼저 확정되어야 그 위에서 타입과 컴포넌트를 설계할 수 있습니다. 골격 없이 기능부터 만들면 구조 변경 시 전체를 다시 손봐야 합니다.

### 예상 소요 시간
0.5일 ~ 1일

### 완료 기준
- [x] `next dev`로 빈 페이지가 정상 구동됨
- [x] Tailwind 클래스가 적용됨을 샘플로 확인
- [x] shadcn/ui 컴포넌트 1개 이상 추가 가능한 상태
- [x] Notion Integration이 대상 데이터베이스에 연결(공유)됨
- [x] Notion DB에 PRD 명시 필드가 모두 생성됨

## 2단계: 공통 모듈/컴포넌트 개발

### 할 일
- `@notionhq/client` 설치 및 Notion API 연동 레이어 구현
  - DB 조회 함수 (`getPublishedProjects()` 등)
  - Notion 응답 → 프로젝트 타입으로 매핑하는 파서
  - 프로젝트 타입 정의 (`types/project.ts`)
- 공통 UI 프리미티브 준비 (shadcn/ui 기반: Card, Badge, Button, Skeleton 등)
- 공통 레이아웃 컴포넌트 (헤더/소개 영역, 페이지 컨테이너)
- 에러/로딩 상태를 위한 공통 유틸 (fetch 실패 처리 등)

### 왜 이 순서인가
핵심 기능(카드 그리드, 필터링)은 "Notion에서 데이터를 어떻게 가져오고 어떤 타입으로 다루는지"와 "카드/배지 등 공통 UI가 이미 존재하는지"에 의존합니다. 데이터 레이어와 공통 컴포넌트를 먼저 만들어야 핵심 기능 단계에서 조립만 하면 됩니다.

### 예상 소요 시간
1일 ~ 1.5일

### 완료 기준
- [x] Notion API 연동 함수가 실제 DB에서 데이터를 정상적으로 가져옴
- [x] 프로젝트 타입 정의가 Notion 필드와 1:1로 매핑됨
- [x] 공통 컴포넌트(Card, Badge 등)가 스토리/샘플 페이지에서 렌더링 확인됨
- [x] API 호출 실패 시 에러를 던지거나 처리할 수 있는 최소 장치 마련

> 참고: `getPublishedProjects()`는 실제 Notion API 호출(인증 → data_source 조회 → filter/sorts 쿼리 → 파싱)까지 정상 동작함을 확인했으나, 연결된 Notion DB에 아직 프로젝트 항목이 0건이라 실제 데이터가 채워진 응답으로는 검증하지 못했다. DB에 항목을 추가한 뒤 재확인 필요.

## 3단계: 핵심 기능 개발

### 할 일
- 프로젝트 카드 그리드 조회 — 공개여부(true)인 항목만 필터링, 정렬순서로 정렬
- `ProjectCard` 컴포넌트 구현 (썸네일, 제목, 설명, 태그 표시)
- 카드 그리드 레이아웃 (`/` 페이지에 배치)
- 태그 기반 필터링 (`TagFilter` 컴포넌트, 클라이언트 상태로 필터링)
- 외부 링크 연결 (카드 클릭 시 GitHub/데모 링크로 새 탭 이동)

### 왜 이 순서인가
PRD의 MVP 핵심 가치(카드 그리드 조회, 태그 필터링, 외부 링크 연결)를 실제로 동작하게 만드는 단계입니다. 공통 모듈(데이터 조회, 카드 컴포넌트)이 이미 준비되어 있으므로, 이 단계는 조립과 상호작용 로직 구현에 집중할 수 있습니다.

### 예상 소요 시간
1.5일 ~ 2일

### 완료 기준
- [ ] `/` 페이지에서 공개된 프로젝트만 카드로 노출됨
- [ ] 카드가 정렬순서 기준 오름차순으로 표시됨
- [ ] 태그 클릭 시 해당 태그를 가진 카드만 필터링됨
- [ ] 카드 클릭 시 외부 링크가 새 탭으로 정상 이동함

## 4단계: 추가 기능 개발

### 할 일
- 빈 상태 화면 구현 (공개 프로젝트 없음 / 필터 결과 없음 안내 문구)
- 반응형 레이아웃 적용 (모바일/태블릿/데스크톱 그리드 컬럼 대응)
- 로딩 상태 UI (Skeleton 등) 및 데이터 fetch 실패 시 사용자 안내
- 상단 소개 텍스트 영역 다듬기
- 기본 SEO 메타데이터 (타이틀, 설명, OG 태그 등)

### 왜 이 순서인가
핵심 기능이 동작한 뒤에야 "핵심 흐름에서 벗어난 경우"(빈 상태, 로딩, 실패)와 "보조적인 사용자 경험"(반응형, SEO)을 다듬는 것이 의미가 있습니다. 핵심 로직이 바뀌면 이 단계의 UI도 다시 손봐야 하므로 항상 3단계 이후에 진행합니다.

### 예상 소요 시간
1일

### 완료 기준
- [ ] 공개 프로젝트가 0개이거나 필터 결과가 없을 때 안내 문구가 노출됨
- [ ] 모바일/데스크톱 등 주요 뷰포트에서 레이아웃이 깨지지 않음
- [ ] 데이터 로딩 중 스켈레톤 또는 로딩 표시가 보임
- [ ] 페이지 타이틀/설명 메타데이터가 설정됨
