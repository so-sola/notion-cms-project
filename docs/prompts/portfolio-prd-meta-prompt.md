# 포트폴리오 웹 MVP PRD 작성용 메타 프롬프트

아이디어 한 줄만 입력하면 실무 PM/PD 수준의 MVP PRD를 Markdown으로 생성하는 재사용 프롬프트입니다. Claude Code에서 그대로 사용할 수 있고, 결과물은 Notion에 바로 붙여넣을 수 있습니다.

## 1. 메타 프롬프트 (재사용 템플릿)

`{{PROJECT_IDEA}}` 자리에 아이디어를 채워 아래 전체를 복사해서 사용하세요.

```markdown
당신은 스타트업과 사이드 프로젝트의 MVP를 다수 설계해온 시니어 Product Manager 겸 Product Designer입니다.
아래 아이디어를 바탕으로 실무 수준의 MVP PRD(Product Requirements Document)를 작성하세요.

[아이디어]
{{PROJECT_IDEA}}

[작성 원칙]
- MVP 범위에만 집중하고, 장황한 설명 없이 핵심만 bullet로 작성한다.
- 정보가 부족하거나 불명확한 부분은 되묻지 말고, 합리적으로 가정한 뒤 "가정" 항목에 명시한다.
- 모든 기능/판단에는 근거를 1줄로 함께 제시한다 (왜 MVP에 포함/제외되는지).
- 결과는 Notion에 그대로 붙여넣을 수 있는 순수 Markdown으로만 작성한다 (HTML 태그 금지, 코드블록/이미지 목업 금지).
- 아래 8개 섹션과 헤더를 그대로, 순서대로 사용한다.

[출력 구조]
## 1. 프로젝트 개요
## 2. 문제 정의 (Problem Statement)
## 3. 목표 (Objectives)
## 4. 타겟 사용자
## 5. 사용자 페르소나
## 6. 핵심 사용자 시나리오 (User Flow)
## 7. 핵심 기능 (MVP Scope)
   - Must Have
   - Out of Scope (MVP 이후)
## 8. 가정 및 제약사항
```

## 2. 사용 방법

1. 위 코드블록 전체를 복사한다.
2. `{{PROJECT_IDEA}}` 자리에 프로젝트 아이디어를 채운다. WHAT(무엇을) / WHO(누구를 위해) / 제약(기간·인력·기술스택)을 함께 적을수록 결과 품질이 높아진다.
3. Claude Code에 통째로 붙여넣고 실행한다.
4. 생성된 Markdown 결과를 Notion 페이지에 그대로 붙여넣는다 (Notion이 Markdown 헤더/리스트/표를 자동 변환).
5. 반복 사용할 경우, Claude Code에서는 `.claude/commands/prd.md`로 저장해 슬래시 커맨드(`/prd`)로 등록하면 매번 복사할 필요 없이 재사용할 수 있다.

## 3. 좋은 입력 예시

> Notion을 CMS로 쓰는 개인 포트폴리오 웹사이트. 프로젝트 카드 목록을 Notion DB로 관리하고, 태그별 필터링이 가능해야 함. 타겟은 채용 담당자와 잠재 클라이언트. Next.js + Notion API 사용 예정, 1인 개발, 2주 내 MVP 목표.

**좋은 이유**: 무엇을(WHAT), 누구를 위해(WHO), 어떤 제약(기술스택·기간·인력)인지가 모두 명시되어 있어 AI가 임의로 가정해야 하는 부분이 최소화되고, 스코프가 실제 상황에 맞게 좁혀진다.

## 4. 나쁜 입력 예시

> 포트폴리오 사이트 만들고 싶어요, 멋있게 해주세요.

**나쁜 이유**: 문제 정의, 타겟, 제약조건이 전혀 없어 AI가 페르소나부터 기능 범위까지 전부 임의로 가정해야 한다. 결과 PRD가 그럴듯해 보여도 실제 의도와 어긋날 확률이 높고, 매번 실행할 때마다 결과가 크게 달라진다.

## 5. 메타 프롬프트를 개선할 수 있는 추가 제안

각 항목은 "언제 필요한지 → 무엇을 추가하는지 → 어떤 형식으로" 순서로 정리했다. 해당 트리거가 발생했을 때만 메타 프롬프트에 반영한다.

1. **기술 스택 제안**
   - 트리거: 인증·결제·실시간 기능처럼 외부 연동이 늘어나 기술 선택 근거를 남겨야 할 때
   - 추가할 것: `[출력 구조]`에 `## 9. 기술 스택 제안` 섹션 추가
   - 형식: Frontend / Backend / DB / 배포 4행 표, 각 행에 "선택 기술"과 "선택 이유(1줄)" 열

2. **우선순위 스코어링 기준**
   - 트리거: 후보 기능이 많아 "7. 핵심 기능(MVP Scope)"의 Must Have/Out of Scope 구분이 주관적으로 느껴질 때
   - 추가할 것: `## 7. 핵심 기능`을 산출하기 전 단계로 스코어링 표를 요구하는 지시문 추가
   - 형식: 기능명 / Impact(1~5) / Effort(1~5) / Score(Impact÷Effort) 4열 표를 만들고, Score 상위 항목만 Must Have로 채택

3. **리스크 및 오픈 이슈**
   - 트리거: Notion API rate limit, 인증 토큰 만료 등 외부 의존성이 있는 프로젝트일 때
   - 추가할 것: `[출력 구조]`에 `## 9. 리스크 및 오픈 이슈` 섹션 추가
   - 형식: 리스크 / 영향도(상·중·하) / 대응 방안 3열 표

4. **Few-shot 예시 첨부**
   - 트리거: 동일 아이디어를 2회 이상 실행했을 때 결과 구조나 톤이 크게 달라지는 경우
   - 추가할 것: 메타 프롬프트 맨 아래에 `[참고 예시]` 섹션 추가
   - 형식: 과거에 잘 작성된 PRD 1개를 200~300자로 요약해 붙여넣기 (전체를 붙이면 프롬프트가 지나치게 길어지므로 압축 버전 권장)

5. **가정 검증 2단계 프롬프트**
   - 트리거: "8. 가정 및 제약사항"에 적힌 가정이 실제와 달라 PRD를 처음부터 다시 돌려야 하는 비효율이 반복될 때
   - 추가할 것: 메타 프롬프트를 1단계(가정 목록만 먼저 출력)와 2단계(사용자 답변을 반영해 전체 PRD 생성)로 분리한 2-pass 버전을 별도 옵션으로 마련
   - 형식: 1단계 출력은 "가정 항목 + 확인이 필요한 질문 1줄"만 담은 짧은 리스트, 2단계는 기존 8개 섹션 템플릿 그대로 사용
